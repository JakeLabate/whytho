Setup

WhyTho runs inside the page you are annotating, so it works on staging, on production, and behind a login.

Your bookmarklet

This is how you start WhyTho on a page. Install it once per browser, then open it on any page you want to annotate.

The bookmarklet is per person: you click it when you need it. This script tag does the opposite, it loads WhyTho for anyone who opens the page, with no clicking. Useful on a staging environment your team lives in.

The token below is your account credential. Anyone who can view the source of that page can take it and write notes as you. Put it on private staging only, never on a production site.

Then

  1. Load the page you want to document and click the bookmarklet.
  2. Choose Select an element, then click it. On a phone, press and hold instead.
  3. Write the reasoning, tag it, save. A numbered pin sticks to the element.
  4. The note saves to your account as you write it, signed with your name.

API

A read only HTTP API over your notes, so they can feed a dashboard, a CI check, or a report instead of being copied by hand.

Your keys

A key reads one workspace: whichever one you are in when you create it. Only a hash is stored, so a key is shown once and cannot be recovered later.

Endpoints

Base URL

Every request needs your key in the Authorization header.

curl -H "Authorization: Bearer why_live_..." \
  "/notes?site=example.com&status=do%20not%20change"
EndpointReturns
GET /meWhat the key can see: its workspace, and how many pages are in scope.
GET /pagesEvery annotated page in that workspace, with a note count each.
GET /notesThe notes themselves, filtered and paginated.

Filters on /notes

siteMatch part of the hostname, e.g. site=jimmiesplace.com
pathPath prefix, e.g. path=/products/
categoryseo, content, tech, a11y, perf, ux
statusdecided, proposed, question, do not change
authorExact display name, e.g. author=Jake Labate
teamExact team name
qFree text inside the note body
sinceISO date, returns notes created on or after it
limit / offsetPage through results. Default 50, maximum 200.
orderoldest to reverse the default newest first

A note looks like this

{
  "data": [
    {
      "id": "n_abc123",
      "url": "https://example.com/pricing/",
      "origin": "https://example.com",
      "path": "/pricing/",
      "page_title": "Pricing",
      "selector": "main > section.hero > h1",
      "element": "h1",
      "element_text": "Same day plumbing repair",
      "body": "Service plus city stays, the phrase carries the local demand.",
      "category": "seo",
      "status": "do not change",
      "author": "Jake Labate",
      "team": "SEO",
      "mentions": [{ "type": "team", "id": "...", "label": "Engineering" }],
      "viewport": { "width": 390, "breakpoint": "mobile" },
      "created_at": "2026-09-09T13:00:00.000Z"
    }
  ],
  "pagination": { "limit": 50, "offset": 0, "returned": 1 }
}

Read only by design. Notes are written by the annotator, where the selector and the viewport can be captured honestly, and nowhere else. A revoked key stops working immediately.
